# Task Trace / 任务脉络

[English](README.md) | 简体中文

Task Trace 是一个 Codex 技能，将项目决策、有意义的变更、实际验证和完成依据连接起来，
保留足够的任务上下文，帮助长任务在中断、交接或上下文压缩后继续推进已授权工作。

可选的恢复加载器能在会话开始时载入已绑定任务的计划摘要和当前检查点。
代理仍需核对最新请求及真实产物，完整行为定义见 [SKILL.md](SKILL.md)。

## 适用场景

- 讨论项目目标或比较存在重要取舍的实现方案。
- 按已确认方案推进跨多个阶段的实施任务。
- 恢复已有决策、执行记录和未完成工作的任务。

普通问答和独立的小改动不需要这套流程，除非它们属于正在跟踪的任务，
或用户显式调用技能。记录量应与任务规模相称。

## 两份文档的职责

| 文档 | 作用 | 内容 |
| --- | --- | --- |
| `PLAN.md` | 说明预期成果和决策 | 范围、已选方案、确认依据、验收标准及简短恢复摘要。 |
| `WORKLOG.md` | 说明实际状态和证据 | 当前检查点、决策理由、有意义的变更、验证结果、必要命令和子任务结果及完成依据。 |

优先沿用项目已有记录。需要新建时遵循项目文档约定，
没有既有约定则默认放在 `docs/tasks/<short-task-name>/`。
[计划模板](assets/PLAN.md)和[执行记录模板](assets/WORKLOG.md)仅作为新建起点，
已有文档不必重新初始化或强制迁移。任务数据保存在项目工作区，不放进技能安装目录。

按用途选择文档。执行日志应链接设计规范和专项验证矩阵，不能替代它们。
工程记录默认留在项目内，除非用户指定其他位置；
使用本技能不代表授权创建 Pages 或将记录迁移到 Pages。

审查、只回答和监控请求默认不写记录，但沿用任务中已有的明确文档写入授权。
只读和禁止写文件的边界同样适用于会话绑定变更。

## 工作流程

1. **讨论并选定方案。** 区分用户确认的目标、假设、实际候选方案和代理建议。
   记录选定方案及范围；方案确认和实施授权分别追踪。
2. **保留选择理由。** 移除已解决的方案比较前保存关键决策依据。
   新证据改变关键取舍时，仅重新讨论受影响的决定，保留其他已达成的共识。
3. **关联变更与证据。** 每项有意义的变更对应已确认目标、选定决策，
   或已授权工作的必要后果，并记录受影响文件和实际验证结果。合并相关编辑，避免逐次记账。
4. **恢复真实状态。** 阅读计划摘要和检查点，区分已确认指示、建议与实际观察，
   再核对相关产物。旧待办和“下一步”记录不能成为新的执行授权。
5. **按范围完成。** 收齐必要命令和子任务结果，完成所需验证。
   约定范围交付后更新一次检查点并报告结果，不追加可选工作或反复检查。

## 安装技能

安装 Git 后，将仓库克隆到 Codex 支持的用户技能目录：

```sh
mkdir -p ~/.agents/skills
git clone https://github.com/Yu03-6/task-trace.git ~/.agents/skills/task-trace
```

如果环境已经使用其他受支持的技能目录，请沿用原位置。
保留一份可发现的安装，不要覆盖已有目录。Codex 会自动检测技能变更；
未出现时可重启。目录与发现规则见
[官方技能文档](https://learn.chatgpt.com/docs/build-skills)。

纯文档流程没有额外运行时依赖。可选自动恢复需要 Python 3.8 或更高版本，
仅使用标准库。安装技能本身不会注册或激活恢复钩子。

从 Project Memory 升级时，请在移动旧安装前遵循[更名迁移步骤](references/recovery.md#migrate-from-project-memory)。

## 使用示例

[配置](agents/openai.yaml)允许自动匹配，也可以显式使用 `$task-trace`。
请求可以使用中文或英文，任务文档遵循项目本身的语言要求。

**先规划并记录，暂不实施**

```text
使用 $task-trace，比较账户同步方案。
可以保存计划和执行记录，但暂时不要实施。
```

**选定方案并实施**

```text
使用 $task-trace。选择方案 A 并实施账户同步，范围不包含支付。
保留选择理由和实际验证证据。
```

**恢复任务**

```text
使用 $task-trace，恢复 docs/tasks/account-sync/ 中记录的任务。
阅读计划和检查点，核对真实工作区，完成已授权范围。
```

## 可选自动恢复

在受支持的宿主上，从稳定的技能安装位置运行：

```sh
python3 ~/.agents/skills/task-trace/scripts/task_trace.py install-hooks
```

安装器在宿主的 `hooks.json` 注册一个 `SessionStart` 处理器，保留其他处理器，
并在首次修改前备份已有配置。它不修改信任设置。
钩子运行前，在 Codex CLI 中打开 `/hooks`，审阅并信任该精确定义；
不能绕过信任机制或自动授予信任。宿主策略也可能禁用钩子。
安装器支持 macOS/Linux；Windows 宿主注册尚未验证。

选定任务记录并获得维护记录的授权后，绑定当前会话。计划文件必须已经存在。
将示例路径替换为实际工作区和任务文档，脚本路径也应对应真实安装位置：

```sh
python3 ~/.agents/skills/task-trace/scripts/task_trace.py bind \
  --workspace /path/to/project \
  --plan docs/tasks/account-sync/PLAN.md \
  --worklog docs/tasks/account-sync/WORKLOG.md
```

绑定默认使用 `CODEX_THREAD_ID`，必要时可显式提供已知的 `--session-id`。
不能从最新会话记录猜测 ID。文档路径可以是绝对路径，也可以相对于绑定的工作区，
但必须位于该工作区内；可以沿用已有文件名。
绑定信息保存在宿主 Codex 主目录下，与任务文档分开。
重新绑定表示明确为该会话选择另一个任务。

离开任务时可以使用 `unbind`；移除已注册处理器可使用 `uninstall-hooks`。
两者都保留任务文档。配置位置、移除命令和手动恢复详情见
[恢复参考](references/recovery.md)。

## 重载内容与边界

- 钩子处理 `startup`、`resume`、`compact` 和 `fork` 会话开始事件。
  明确排除 `clear`；不安装 `Stop` 钩子，也不会强制继续工作。
- 使用事件传入的精确会话 ID，并检查当前目录是否位于绑定的工作区内。
  会话未绑定或工作区不匹配时不注入上下文；新 fork 不继承绑定，也不会猜测最近任务。
- 读取 `## Recovery summary` 和 `## Current checkpoint` 的有限长度片段。
  缺少标题时读取文件开头的有限片段并标注回退方式；历史按需查阅，已有记录无需重写。
- 重载本身只读。缺失记录会被标明；输入无效或绑定失效不会阻塞本轮工作。
  加载器不写任务记录、不总结对话，载入的历史只提供上下文，不构成执行授权。

没有注册并受信任的钩子时，仍可按同样的手动流程恢复：
定位正确任务文档，读取相关上下文，核对实际产物，
然后仅在当前授权范围内继续工作。

## 实际限制

自动匹配由模型判断，并非每次都会触发。恢复依赖记录及时更新及对相关事实的核对，
记录中的成功描述不能替代验证证据。
仓库中的隔离测试不代表已在安装宿主上激活自动恢复；
每个宿主都需要支持、注册并信任钩子，才能实际运行。
本技能不提供后台监控，也不能保证避免上下文丢失。
加载已完成的检查点不意味着要求继续新增工作。
