# Project Memory / 项目记忆

[English](README.md) | 简体中文

Project Memory 是一个 Codex 技能，用项目内的 Markdown 文档保存方案取舍、执行边界和当前进展，帮助长任务在中断或交接后继续推进。

它将“准备做什么”和“实际做到哪里”分别记录，恢复工作时再核对代码、文件及验证证据。技能的完整行为定义见 [SKILL.md](SKILL.md)。

## 适用场景

- 讨论较复杂的项目目标、约束和实现方案，需要保留选择理由。
- 执行跨多个步骤或会话的任务，需要明确已完成事项和下一步。
- 接手或恢复已有任务，需要核对计划、执行记录与实际产物。
- 只规划并保存讨论结果，暂不实施。

普通问答和独立的小改动通常不需要这套记录；也可以显式调用技能用于较小的任务，记录量应与任务规模相称。

## 两份文档的职责

| 文档 | 记录内容 | 主要作用 |
| --- | --- | --- |
| `PLAN.md` | 目标、验收标准、范围、约束、待定方案、已选方案及执行授权 | 说明当前计划及其依据 |
| `WORKLOG.md` | 当前检查点、决策理由、实际变更、验证证据、失败路径和下一步 | 说明真实进展并支持恢复 |

优先沿用项目已有的计划和工作记录，避免维护并行的事实来源。没有既有约定时，默认放在任务工作区的 `docs/tasks/<short-task-name>/`，并让两份文档相互链接。

[计划模板](assets/PLAN.md)和[执行记录模板](assets/WORKLOG.md)仅在创建新任务文档时使用。填写已知事实，删除无关章节和模板说明；已有记录可以保留原有结构。

## 工作流程

1. **建立任务上下文。** 区分已确认目标、约束、待核实假设和未决问题，并定位已有记录。
2. **讨论实际选项。** 在存在有意义的替代方案时比较收益、成本、风险和可逆性，记录推荐理由。
3. **记录决策与授权。** 分别追踪方案是否确定、实施是否获准；确认方案不等于授权开始执行。
4. **收敛计划。** 将选定方案及重要取舍写入决策历史，再从计划中移除已解决的比较内容。
5. **维护执行检查点。** 按有意义的变更单元记录实际状态、验证结果和剩余工作，保留值得避免的失败路径。
6. **恢复并完成。** 阅读当前计划和检查点，核对相关产物，更新差异后继续下一项已授权工作；完成时记录结果和限制。

执行记录顶部保留紧凑的当前检查点，历史只记录有助于理解或恢复工作的内容。多人或多代理协作时，由一个负责人整合共享记录。

## 安装

安装 Git 后，将仓库克隆到 Codex 支持的用户技能目录：

```sh
mkdir -p ~/.agents/skills
git clone https://github.com/Yu03-6/project-memory.git ~/.agents/skills/project-memory
```

如果已经在其他受支持的技能目录安装，请沿用原位置，避免重复安装。目标目录已存在时，先检查其内容，不要覆盖。

Codex 会自动检测技能变更；如果技能没有出现，可重启 Codex。本技能没有额外运行时依赖。技能目录及安装方式可参考 [Codex 官方技能文档](https://learn.chatgpt.com/docs/build-skills)。

[配置文件](agents/openai.yaml)允许隐式调用，Codex 可根据任务内容匹配技能；也可以在请求中显式使用 `$project-memory`。自动匹配并不保证每次触发。

## 使用示例

### 先规划并记录，暂不实施

```text
使用 $project-memory，比较这个项目的数据同步方案，记录目标、约束和
主要取舍。可以创建或更新计划与工作记录，但暂时不要修改应用代码或实施方案。
```

### 选定方案并授权实施

```text
采用刚才讨论的方案 A，并开始实施，范围限于账户同步，不包含支付。
使用 $project-memory 保存选择理由、执行范围和后续验证结果。
```

### 恢复任务并核对实际状态

```text
使用 $project-memory，恢复 docs/tasks/account-sync/ 中记录的任务。
先读取计划和当前检查点，核对相关代码、工作区差异及验证证据，
更新实际状态，再继续下一项已授权工作。
```

## 仓库结构

可以使用中文或英文提出请求；生成的任务文档遵循项目自身的语言要求。

```text
project-memory/
├── SKILL.md             # 技能行为与工作流程
├── agents/openai.yaml   # 显示信息与隐式调用配置
├── assets/
│   ├── PLAN.md          # 新建计划时使用的模板
│   └── WORKLOG.md       # 新建执行记录时使用的模板
├── README.md            # 英文说明
└── README.zh-CN.md      # 中文说明
```

本仓库提供技能说明、配置和模板。用户任务记录保存在相应任务工作区，不写入技能安装目录。

## 实际限制

- 技能依赖代理及时更新、定位并读取记录，不能保证完全避免上下文丢失，也不提供后台监控或自动执行服务。
- 恢复时仍需检查真实产物；历史记录中的成功描述不能代替验证证据，尝试过的命令也不等于验证通过。
- 技能不扩大执行权限，并遵守只回答、只读和禁止写文件等边界。无法写入时，应在对话中提供必要检查点并说明未持久化。
- 记录应保持精简，不保存秘密值、完整对话或不必要的原始工具输出。过长历史可按项目已有约定整理，保留关键决策理由和恢复证据。
